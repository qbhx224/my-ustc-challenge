# 静态链表

## 是什么

用**数组**模拟链表。每个数组元素存数据 + "下一个元素的下标"（代替指针）。

适用场景：没有指针的语言（如早期 BASIC、FORTRAN），考试偶尔考。

## 结构定义

```c
#define MaxSize 100
typedef struct {
    int data;    // 数据
    int next;    // 下一个元素的数组下标（类似指针）
} SLinkList[MaxSize];
```

## 存储方式

```
下标：   0    1    2    3    4    5
data：  [空] [10] [30] [20] [空] [空]
next：  [2]  [3]  [0]  [-1] [空] [空]
         ↑                        ↑
        头结点（next=2）         空闲链头
```

- 下标 0 当头结点，next 指向第一个数据元素
- next = -1 表示链表结束（相当于 NULL）
- 空闲位置也串成一条链，方便分配和回收

## 操作特点

- 插入/删除：和链表一样改 "next" 值，不需要移动元素
- 查找：和链表一样从头遍历
- 没有真正的 malloc/free，用空闲链管理空间

## 考试频率

低，了解即可。主要考：怎么用数组下标模拟指针操作。

# 顺序表 vs 链表 · 全面对比

## 核心区别

| 维度 | 顺序表 | 链表 |
|------|--------|------|
| 存储方式 | 连续内存 | 分散内存 + 指针 |
| 随机访问 | **O(1)** | O(n) |
| 插入/删除 | O(n) 移动元素 | **O(1)** 改指针（已知位置时） |
| 空间 | 预分配，可能浪费 | 动态分配，按需申请 |
| 缓存友好 | **好**（连续访问） | 差（跳跃访问） |

## 选择策略

**用顺序表的场景**：
- 频繁按下标查找（如二分查找）
- 数据量基本固定
- 需要频繁遍历

**用链表的场景**：
- 频繁在任意位置插入/删除
- 数据量变化大，无法预估
- 不需要随机访问

## 易混淆点

1. **"链表插入删除 O(1)"是假设有前驱指针**
   - 如果要先按位查找再插入，总复杂度是 O(n) + O(1) = O(n)
   - 顺序表插入也是 O(n)
   - 所以"链表插入比顺序表快"不是绝对的

2. **顺序表的缓存优势**
   - CPU 缓存对连续内存友好，顺序表遍历比链表快很多
   - 这是课本不讲但实际很重要的点

3. **链表的空间开销**
   - 每个节点多一个指针（64位系统占8字节）
   - 数据量小时，指针开销占比大

## 考试常考题型

- "以下哪个场景适合用链表/顺序表"（选择题）
- 给一段操作序列，问用顺序表还是链表更高效
- 时间复杂度比较（注意"已知前驱"这个前提）
